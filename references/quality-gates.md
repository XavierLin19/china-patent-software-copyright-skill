# 质量检查与门禁

按用户选择的子流程执行，不相关项标记为“不适用”，不得为了通过门禁伪造证据。硬门禁未通过时，交付限于审阅摘要、结构草案或问题清单，并明确阻断原因。

## 共同门禁

- [ ] 所有输入有来源 ID、读取状态、审阅范围及关键限制。
- [ ] 进入交付物的实质陈述均可回指 `F` 事实和来源位置，状态准确。
- [ ] 推断、用户确认、未知、冲突没有混写成已证实事实。
- [ ] 用户明确确认了依赖确认才能继续的范围、字段或选择。
- [ ] 未复制凭据/密钥；私有材料未在未经许可时发送到外部服务。
- [ ] 草稿的名称、版本、术语、数字、图表和引用保持一致。
- [ ] 未核验的现行表格/规则/格式要求标为待复核。
- [ ] 交付目录区分内部台账、草稿和最终导出件；迭代有版本记录。

## 专利门禁

- [ ] 材料逐页/逐项检查状态如实；公式、图、表、代码未审阅处已指出。
- [ ] 检索记录包含来源、查询式、日期、筛选边界、同族处理和全文核验状态。
- [ ] 技术特征与来源/现有技术/差异/效果逐项对应；没有把多份文献拼成单篇公开。
- [ ] 创新对齐和起草范围对齐分别完成；未确认时未输出完整申请包。
- [ ] 每项权利要求特征有说明书支持及本案来源依据；没有凑权项或加入无证据替代方案。
- [ ] 背景、技术问题、手段、效果、实施方式、权利要求、附图之间一致。
- [ ] 数字、参数、公式、符号、单位、图号和术语有来源且全文一致。
- [ ] 未把未验证效果写成实测结论；未将样本文献写成案件事实。
- [ ] 法律判断和提交形式问题标明由专业人士按当前规则复核。

## 软著门禁

- [ ] 软件身份、名称、版本、著作权人、日期、发表状态等字段均经用户确认或明确留空。
- [ ] 功能描述由真实项目资料支持，不从测试/demo/相似软件推断。
- [ ] 操作手册每个流程都能回指真实页面/文档/代码/截图证据；不把技术栈当功能。
- [ ] 代码选择经用户确认，逐文件可追溯，源代码未由 AI 生成或内容性改写。
- [ ] 第三方、生成、构建、二进制和敏感文件的排除范围已说明。
- [ ] 实际导出件已检查页数、分页、名称/版本一致性、页眉、可读性和截图位置；未导出的格式不宣称已验证。
- [ ] 当前官方表单和提交规则有来源/核验日期，或者保留待复核说明。
