# 统一来源与证据台账

## 目的

让专利和软著输出能够从每个关键陈述回溯到具体来源，同时区分来源事实、推断、用户确认和未知项。该账本由助手以普通 Markdown 维护即可；表格模板见 `../templates/evidence-ledger.md`。

## 来源登记

每份来源分配稳定 ID（`S001` 起），至少登记：

| 字段 | 内容 |
|---|---|
| source_id | 稳定 ID |
| 文件/网页 | 原始名称或标题、来源路径/URL |
| 类型/版本 | 源代码、需求、报告、图片、专利全文等；版本或日期 |
| 完整性 | 已读取、部分读取、无法读取、仅元数据 |
| 审阅范围 | 文件全篇、页码、章节、代码路径/行号 |
| 指纹 | SHA-256（工具可用时）；不可用则说明 |
| 可信度/边界 | 一手或二手、样本局限、转换问题、冲突 |
| 敏感边界 | 需要排除或脱敏的范围，不记录秘密值 |

不以文件名、扩展名或存在性代替内容审阅。转换后的副本需要链接原始 `source_id`，记录转换工具和可能的内容损失。

## 事实/主张登记

每条重要技术、业务或申请字段陈述分配 `F001` 起，包含：

- 陈述原文或简明摘要；
- 状态：`SUPPORTED`、`INFERRED`、`USER_CONFIRMED`、`UNKNOWN`、`CONFLICT`、`OUT_OF_SCOPE`；
- 来源 ID 和精确位置；
- 推理前提（仅 `INFERRED`）；
- 适用范围、反例/限制、与其他来源的冲突；
- 使用位置：权利要求/说明书段落/操作手册章节/申请字段等。

一个事实不得指向无关的大文件作为唯一凭据，应定位到页、段、表格、图、代码符号/行或用户确认记录。

## 待确认项

每项分配 `Q001` 起，记录问题、需要谁回答、为何影响输出、关联事实/文件、优先级、当前状态和用户答复。涉及范围、权属、日期、效果或核心技术机制的未决项不得埋在正文里。

## 复核与失效

来源更新、代码分支变化、外部网页不可访问、用户纠正关键事实或模板/规则变化时，记录新版本并复核依赖该来源的事实与文档。旧证据保留为历史，不把已经失效的引用当作当前依据。
